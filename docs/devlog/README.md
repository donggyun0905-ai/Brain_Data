# 개발 일지 — 날짜별 기록

하루에 한 파일이다. 그날 **무엇을 했고, 어떤 코드를 어떻게 썼고, 왜 그 방식을 골랐고,
다른 방법과 무엇이 달랐는지**를 코드와 함께 남긴다. 처음 읽는 사람이 이 파일만 따라가도
프로젝트가 어떻게 여기까지 왔는지 알 수 있게 쓴다.

- **지금 상황과 다음 할 일**은 `docs/devlog.md` (여기 말고 그쪽)
- **결정의 근거**는 `docs/adr/`. 일지는 '그날의 이야기', ADR은 '결정문'이다
- **지켜야 할 규칙**은 `CLAUDE.md`

## 쓰는 규칙
1. 코드를 바꿨으면 **바꾼 코드를 붙이고**, 바꾸기 전과 무엇이 다른지 적는다
2. 고른 방식 옆에 **버린 방식과 그 이유**를 적는다. 이유 없는 선택은 나중에 되돌릴 수 없다
3. 측정값은 **3회 반복 중앙값(범위)**. 한 번만 쟀으면 그렇게 밝힌다
4. 추측은 '추측'이라고 쓴다
5. **실패와 헛걸음도 쓴다.** 같은 실수를 두 번 하지 않기 위한 기록이다
