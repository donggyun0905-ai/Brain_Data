# ADR-0006: 개발은 PC의 가벼운 설정, 실험은 AWS 스팟 인스턴스

- 날짜: 2026-10-17 / 상태: 채택 (기획서 '실행 환경과 예산'을 구체화)

## 상황
기획서는 개발을 개인 노트북(0원)에서, 본 실험(E1~E6, 수면 재생)을 AWS 서울 리전 32GB급 스팟
인스턴스(약 20만 원)에서 하도록 정했다. 개발 노트북에서 core 묶음(약 9GB)이 돈다는 가정이었다.

실제 개발 PC는 메모리 15.4GB, Docker(WSL2) 할당 8GB이고, core의 메모리 한도 합은 약 11GB다.
PyCharm과 브라우저를 함께 쓰면 core 전체를 띄울 수 없다.

## 후보
| 방식 | 판정 |
| --- | --- |
| WSL 메모리 할당을 12GB 이상으로 늘림 | 탈락. Windows·PyCharm·브라우저 몫이 3GB대로 줄어 개발이 느려짐 |
| 처음부터 EC2에서 개발 | 보류. 상시 켜두면 예산을 빨리 씀. 필요할 때만 쓰는 실험 장비로 둠 |
| 관리형 서비스(MSK, Managed Flink) | 탈락. 예산 초과, 설계 원칙 10 |
| **PC는 가벼운 덮어쓰기 설정, 실험은 EC2 스팟** | **채택** |

## 결과
- `docker-compose.local.yml`: Kafka 힙 512MB, JobManager 900MB, TaskManager 1개(1.6GB), ClickHouse 1GB.
  Kafka + Flink만 켜면 약 1.1GB 사용 (2026-10-17 측정)
- 기본 `docker-compose.yml`은 실험 장비 기준으로 그대로 둔다. 같은 파일을 EC2에서 쓴다
- PC에서 잰 처리량은 기능 확인용으로만 쓰고, E1 기준선 같은 실험 수치는 실험 장비에서만 잰다
- EC2 준비는 11월 중에 한다 (12/6 E1 전까지)
  - Terraform으로 인스턴스·S3·보안 그룹을 만들고 지우는 코드를 저장소에 둔다 (재현성, 비용 통제)
  - 기획서의 비용 안전장치 그대로: AWS Budgets 경보, NAT Gateway 금지, 실험 종료 시 자동 종료, 결과는 S3
- 함께 고친 것: 기본 설정의 JobManager 메모리(이미지 기본값 1,600MB)가 컨테이너 한도 1,500MB를 넘어
  1,200MB로 지정
