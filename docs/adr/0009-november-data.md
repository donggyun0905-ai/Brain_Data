# ADR-0009: 실제 데이터는 REES46 2019년 11월을 쓴다 (10월 대신)

- 날짜: 2026-10-18 / 상태: 채택

## 상황
기획서는 REES46 2019-Oct.csv를 전제했다. 받은 파일은 2019-Nov.csv(9.0GB)였다. 형식은 같다.

## 후보
| 방식 | 판정 |
| --- | --- |
| 10월 다시 받기 | 기획서 그대로. 하지만 폭증 장면은 재생기로 인공적으로 만들어야 함 |
| **11월 사용** | **채택**. 11/15~17 대형 할인 기간에 하루 이벤트가 평소의 약 3.7배 → 실제 폭증을 진짜 데이터로 재생 가능 |
| 둘 다 | 나중에 필요하면 10월을 추가 (수면 재생 비교용 등) |

## 실측 (tools/profile_data.py, 2026-10-18)
- 67,501,979행, 2019-11-01 00:00 ~ 11-30 23:59 (UTC), 30일 모두 있음
- 평소 하루 145만~200만 건, 11/14 307만, **11/15~17 622만~650만**, 가장 바쁜 시간 11/17 14시 48만 건
- 이벤트 비율: 조회 94.15%, 장바구니 4.49%, 구매 1.36% (가정 92 / 6.5 / 1.5). remove_from_cart 없음
- 완전 중복 행 100,530건 (0.149%)
- 사용자 3,696,117명. 상위 1%가 조회의 17.5%, 상위 0.1%가 4.0%. 1인 최대 22,926건 (봇으로 추측)
- 실제 시간 평균 26건/초, p99 126건, 최대 243건 → 100배속 평균 약 2,600건/초

## 결과
- 실측 비율로 제어기 비교 시뮬레이션을 다시 돌렸다: 결론 같음 (예측형 p99 0.1초, 단계형 1.9초, 버림 58%)
- `prepare`를 2단계로 바꿈. 한 달을 한 번에 정렬하면 PC 메모리 부족으로 중단됨 (날짜별로 나누기 7분 + 하루씩 정렬 3분)
- 기본 명령·실행 구성의 예시 경로를 `2019-11`로 바꿈
- E1 기준선과 '폭증' 실험의 재생 구간 후보: 평소 날(예: 11/5)과 폭증 날(11/15~17)
