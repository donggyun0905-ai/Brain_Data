# ADR-0016: ClickHouse 적재 확인 완료, 검증 도구가 조용히 거짓말하지 않게 고침

- 날짜: 2026-10-19 / 상태: 채택 (개발 일지 2-1 완료)

## 상황
집 PC는 전체 흐름(→ ClickHouse)을 **가짜 데이터로만** 확인했다 (2026-10-17).
실제 11월 데이터로 재생기 → Kafka → Flink → ClickHouse까지 값이 맞는지, 그리고 같은 창이
두 번 들어와도 ReplacingMergeTree가 덮어쓰는지(설계 원칙 9)가 남아 있었다.

도구: `tools/verify_clickhouse.py`. 일지의 지시대로 `verify_flink.py`의 정답 계산을 재사용한다.
자료: 11/17 14:00~14:06, 46,564건 (조회 41,703 / 장바구니 3,473 / 구매 1,388). 닫히는 창 5개.

(오프라인 모형 49.0%). 자세한 내용은 ADR-0015.

## 이식성 문제 (같이 고침)
`verify_flink.py` · `verify_controller.py` · `bench_signals.py`가 컨테이너 이름을
`data-brain-kafka-1`로 박아 두고 있었다. compose 프로젝트 이름은 폴더 이름에서 만들어지므로
폴더가 `DataBrain`인 PC에서는 `databrain-*`로 떠서 **검증 도구가 전부 실패한다.**

→ 도구 8군데를 고치는 대신 `docker-compose.yml`에 **`name: data-brain`을 박았다.**
폴더 이름이 무엇이든 컨테이너 이름이 같아져 두 PC에서 도구가 그대로 돈다.

## 가장 큰 교훈: 검증 도구가 조용히 잘못된 결론을 내는 것
이번에 같은 종류의 실수를 **세 번** 했다. 셋 다 '도구가 실패를 숨기거나 성급히 판정'한 것이다.

1. **`verify_flink.replay()`는 stderr를 버리고 stdout 60자만 찍는다.** 경로가 틀려 한 건도
   안 보냈는데 조용히 다음으로 넘어가 4분을 기다렸다 → 자체 `replay()`에서 종료 코드를 보고 터뜨린다.
   재생 뒤에는 이벤트 토픽 건수가 0이 아닌지도 확인한다
2. **ClickHouse 행 수만 세며 기다리면 안 된다.** 구매 쪽(1,388건)이 먼저 끝나 조용해지자
   메인 쪽(45,176건)이 아직 계산 중인데도 빠져나와 **'agg_minute 0행'으로 오판**했다
3. **Flink 출력 건수만 봐도 같은 일이 난다.** 메인의 2단계 집계는 한참 읽다가 창이 닫힐 때
   몰아서 내보내므로, 읽는 동안 출력은 조용하다
   → `wait_pipeline`은 **'집계 토픽 건수'와 '작업이 읽은 건수'가 둘 다 멈춘 뒤에야** 적재를 기다린다

판정도 갈라 적는다. 예전 코드는 `1회차 == 2회차`만 보고 1회차가 이미 틀렸는데도 '실패'라고
보고했다. 이제 **1회차가 온전히 맞았나 → 중복이 실제로 들어왔나 → 그래도 `FINAL`이 같은가**
순서로 보고, 조건이 안 되면 **'판정 불가'**로 쓴다. 틀린 판정보다 판정 불가가 낫다.

### 사람이 지킬 규칙
검증이 돌고 있는 동안에는 스택을 **조회만** 한다. 이번에 돌고 있는 검증이 띄운 Flink 작업을
'수동 제출한 것'으로 착각해 취소해 검증을 깨뜨렸다.

## 함께 알게 된 것
- `init.sql`은 `CREATE TABLE IF NOT EXISTS`이고 ClickHouse 이미지는 익명 볼륨을 쓴다.
  열을 늘려도 기존 DB에는 반영되지 않고, `--force-recreate`로도 안 된다
  → 개발 중에는 `docker compose rm -sfv clickhouse` 후 다시 띄우고,
  데이터가 쌓인 뒤에는 `ALTER TABLE ... ADD COLUMN`을 쓴다
- 학교 PC(Docker 8GB)에서 kafka·jobmanager·taskmanager·clickhouse를 켜면 실제 사용량은 약 1.8GB다
  (한도 합 약 5GB). 집 PC 실측 2.5GB와 같은 수준

## 남은 일
- 제어기까지 포함한 전체 흐름을 실제 데이터로 한 번 (제어기는 아직 이 PC에서 띄우지 않았다)
- Kafka에 볼륨 추가 (일지 2-2). 지금은 `down`하면 토픽 데이터가 사라져 7일 보관 원칙과 안 맞는다
- `verify_flink.py`의 `replay()`에도 같은 보강을 적용 (지금은 `verify_clickhouse.py`만 고쳤다)
