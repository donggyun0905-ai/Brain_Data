# ADR-0011: 상위 사용자 기준을 20건에서 50건으로 올린다 (봇 안전장치)

- 날짜: 2026-10-18 / 상태: 채택 / 관련: ADR-0010 (판정 방식은 그대로, 기준값만 바꿈), ADR-0003

## 상황
ADR-0010에서 "30분 감쇠 건수 20건"을 골랐다. 그 뒤 세션 지표(경로·체류·담기 전 조회)를 재 보니
20건에서는 폭증 날 경로가 36%만 남았다. 30건을 검토하다가, 30건도 낮은지 확인하려고 40·50·75·100건까지 쟀다.

## 측정 (tools/compare_heavy.py, 각 날짜 14시 1시간, 통과 비율 10%, 시드 10개 × 3묶음 중앙값(범위))

| 감쇠 30분 20건 | 8.8% | 51.8 (51.3~52.8)% | 35.9% | 80.4% | 23.8% | 3.2% | 32.6 (32.5~33.8)% | 57.8% |

비율 5%에서도 순서는 같다 (11/17 경로 보존: 20건 26.5%, 30건 51.2%, 50건 88.1%).
퍼널 오차 p95는 모든 기준에서 1%p 안팎으로 같다.

## 알게 된 것
1. **30건부터는 범주·분 오차가 "사용자 해시만"과 범위 안에서 같다.** 정확도 이득은 20건에서도 2.5%p뿐이었다
2. 기준을 올릴수록 세션 지표는 계속 좋아진다. 30건도 경로의 38%를 끊는다
3. 이 데이터에는 봇처럼 몰아 보는 사용자가 없다 (사용자·시간당 최대 195건, 분당 최대 13건).
   그래서 실제 데이터에서는 상위 사용자 처리가 정확도를 거의 바꾸지 못한다
4. 상위 사용자 처리를 아예 빼지 않는 이유: 한 사용자가 수천 건을 만드는 경우(봇·크롤러)에는
   사용자 해시가 그 사용자를 통째로 넣거나 빼서 오차가 크게 흔들린다 (ADR-0003 시뮬레이션, 파레토 분포 가정)

## 결정
- 판정 방식은 ADR-0010 그대로 (이벤트 시각, 30분 감쇠, 사용자별 정확 집계). **기준만 50건**으로 올린다
- 의미: 꾸준히 시간당 약 100건(36초에 1건) 넘게 보는 사용자. 분당 10건 보는 봇은 약 6분 안에 잡힌다
- 역할을 "정확도 개선"에서 **"봇 같은 극단적 사용자만 잡는 안전장치"**로 바꾼다
- 75건 이상은 실제 데이터에서 아무도 잡지 않아 안전장치가 시험되지 않으므로, 폭증 날 소수(0.3%)가 잡히는 50건으로 한다

## 확인 1: 가짜 봇을 넣어도 안전장치가 작동하는가 (2026-10-18)
`tools/compare_heavy.py <날짜> 14 <봇 수> <분당 건수>`: 봇마다 조회 많은 범주 하나를 골라 1시간 내내 일정 간격으로 본다.
통과 비율 10%, 시드 10개 × 3묶음 중앙값(범위). 실제 최대 사용자는 시간당 195건, 봇은 시간당 600건·1,800건이다.

- 봇이 많으면 사용자 해시만으로는 오차가 크게 흔들린다 (봇이 통째로 들어가면 10배로 부풀려짐, 범위가 15%p 넘게 벌어짐).
  50건 기준은 봇 조회의 97%를 이벤트 단위로 넘겨 봇이 없을 때 수준(53~54%)으로 되돌린다 → **안전장치가 작동한다**
- 봇이 적고 느리면(분당 10건) 차이가 작다. 놓친 9%는 봇이 기준에 닿기까지 처음 약 5분이다
- 20건과 50건의 봇 대처 차이는 작다 (봇 이벤트 단위 98.9% vs 97.2%)
- 봇을 넣으면 경로 보존 수치에 봇 세션의 경로까지 섞여서 이 비교에는 쓰지 않았다
- "봇 범주·분" 칸 오차도 출력되지만, 조회가 적은 칸까지 넣어 0건 추정(100%)이 많아 판단에 쓰지 않았다

## 확인 2: Flink가 50건 기준으로 같은 판정을 내리는가 (2026-10-18)
`tools/verify_flink.py`는 전부 통과(비율 1) 상태라 기준을 시험하지 못한다. 그래서 `tools/verify_shedding.py`를 만들었다
- 데이터: 11/17 13:50~14:10 실제 158,078건 + 가짜 봇 5개(분당 20건) 2,000건
- 조회 비율 10%로 고정, 5배속 실시간 재생, PC 설정(Flink 병렬 1)
- 정답: 같은 이벤트를 이벤트 시각 순으로 `HeavyUserTracker()` + `keep()`에 넣어 센 (범주, 1분)별 남은 건수와 1/비율 합
- 결과 3회 모두: **2,161칸 중 2,161칸 남은 건수 일치, 추정값(1/비율 합) 불일치 0, 남는 칸 0**.
  상위 판정 10명(봇 5개 모두 + 실제 사용자 5명), 이벤트 단위 조회 1.22%

## 영향
- `sampling/heavy.py` 기본값 `threshold=50.0`, 테스트 추가 (기본값이 봇은 잡고 많이 보는 사람은 안 잡는지)
- `docs/sampling-cctv.html` 데이터를 새 측정값으로 바꾸고 채택 표시를 50건으로 옮김
- 남은 일: Flink 병렬도를 2 이상으로 올릴 때 확인 (추측, 미확인). 조회 토픽은 12칸, 장바구니 토픽은 6칸이라
  한 사용자의 조회와 장바구니가 서로 다른 필터 작업으로 갈 수 있다. 그러면 그 사용자의 건수가 작업마다 나뉘어 세어진다.
  조회가 94%라 영향은 작을 것으로 보지만, AWS에서 `verify_shedding.py`를 병렬 2 이상으로 다시 돌려 본다
